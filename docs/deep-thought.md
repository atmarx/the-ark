# Deep Thought

The LLM expansion pack.  Six language models and the llama.cpp builds to run
them, laid on top of a stamped drive.  About 75 GB.

Weights are a kind of knowledge too, but a different kind from a ZIM.  An
article has an author and sources; a model gives a fluent paraphrase that is
sometimes wrong.  The pack is there to help people find their way into the
library, and the drive README says so plainly.

## Using it

```bash
./ark sync deep-thought                          # download and verify (~75 GB)
./ark status deep-thought                        # what's here, what's missing
./ark verify deep-thought                        # re-check every sha256
./ark stamp mega /dev/sdX --pack=deep-thought    # new drive: loadout + pack
./ark clone deep-thought /media/THE-ARK          # existing drive: add the pack
```

`deep-thought.yml` sets `pack: true`, which changes three things:

- `ark sync` skips the Kiwix catalog and the drive README.
- `ark clone` uses `rclone copy` instead of `rclone sync`, so it adds the
  `models/` folder without deleting the loadout already on the drive.
- `ark stamp --pack=NAME` copies the pack after the loadout.  It checks that
  the loadout and packs fit before it erases anything.

Mega plus the pack is about 1,040 GB, so it fits a 2 TB drive.  Medium plus the
pack fits a 1 TB drive.

### Using models you already have

If a GGUF library is already on disk, point `models_source` in the staging
config (or `ARK_MODELS_SOURCE`) at it.  `ark sync` checks each matching
file's sha256 and links to it instead of downloading.  A file whose local
name differs from the upstream name can say so with `source_file:`.
Staging is a symlink farm already, and `stamp` and `clone` copy what the
links point to.

## What's on the drive

```
models/
  README.txt            what these are, how to start one, and the caveat
  start-ai.bat          Windows launcher (runs start-ai.ps1)
  start-ai.sh           macOS and Linux launcher
  models.tsv            the list the launchers read (generated by sync)
  LICENSE-Apache-2.0.txt
  llama.cpp/            pinned release archives, one per platform
  <model-id>/           the .gguf, its vision projector (mmproj), any
                        upstream license files
```

The launcher reads the computer's RAM and starts the largest model marked
`auto: true` that fits.  It unpacks llama.cpp into the user's cache folder
the first time, because exFAT can't hold the symlinks in the Linux and macOS
archives.  It uses the Vulkan build when a Vulkan loader is installed
(`ARK_AI_CPU=1` turns that off).  Then it starts `llama-server` on
127.0.0.1:8081 with a 16K context.  The server's built-in chat page is the
interface, and it accepts images for models with a vision projector.

because they crawl on a CPU.  With a 24 GB GPU they're the strongest pair,
and they come from different labs, which makes them useful for checking
each other.

## Choosing models

The rule is **stock releases only**: the maker's own weights, or a straight
quantization of them.  No fine-tunes, merges, distills, or "abliterated" and
"uncensored" variants.  These drives go to strangers, and nobody has
evaluated what a community fine-tune changed.

Where the maker publishes its own GGUF (Google's QAT builds, which were
trained to hold up at 4 bits), use that.  Otherwise use a well-known
quantizer (ggml-org, Unsloth) and say so in the note.

To add one:

1. Find the repo and file on Hugging Face.
2. Pin the revision and copy each file's size and sha256 (the LFS oid):
   ```bash
   repo=google/gemma-4-12B-it-qat-q4_0-gguf
   curl -s https://huggingface.co/api/models/$repo | jq -r .sha
   curl -s https://huggingface.co/api/models/$repo/tree/main \
     | jq -r '.[] | select(.path|test("gguf$")) | [.path, .size, .lfs.oid] | @tsv'
   ```
3. Add an entry under `models:` with `id`, `name`, `ram_gb`, `auto`,
   `license`, `repo`, `revision`, `note`, and `files` (the vision projector
   gets `role: mmproj`).  If the original repo ships a LICENSE or usage
   policy and the GGUF repo doesn't, list it under `license_files:` with a
   pinned URL.
4. Add a line to `templates/models/README.txt` in Zim's voice.

To move to a newer llama.cpp, change `llama_cpp.release` and each asset's
filename and sha256.  GitHub lists the sha256 in the release's asset
`digest` field.  Test the launcher against a small model before stamping.
